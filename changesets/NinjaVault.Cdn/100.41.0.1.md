# NinjaVault.Cdn 100.41.0.1

Date: 2026-09-28
Type: Major

## Changes
- First public release on nuget.org.
- `AddNinjaVaultCdn(configuration)` / `AddNinjaVaultCdn(options => ...)` registers `INinjaVaultCdnClient` through
  `NinjaVault.Http`, so every CDN call is logged and correlation-aware. Both return `IHttpClientBuilder` so callers
  can chain extra handlers (e.g. resilience).
- Client covers access validation, bucket discovery, multipart upload, file listing/search, metadata, usage summary,
  authenticated download, soft delete, public URL building, and single/batch presigned URLs.
- CDN error envelopes map to `CdnApiException` (status code, CDN error code, description, trace id, validation
  details, `Retry-After`).
- Request URIs are built from `BaseUrl` directly, so a `BaseUrl` with a path prefix (`https://host/cdn`) works and
  the shared `HttpClient.BaseAddress` is never mutated.
- `DeleteAsync` accepts `204 No Content` as well as an envelope response.
- Download streams forward async reads instead of falling back to blocking reads.
- `User-Agent` is `NinjaVault.Cdn/<assembly version>`.
- Targets `net8.0`, `net9.0` and `net10.0`.

## Why
- Let external teams integrate with the NinjaVault CDN Server by installing one package instead of hand-rolling
  API-key headers, multipart fields, object-key encoding and the JSON envelope.

## Breaking Changes
- None (first public release). Configuration section is `NinjaVault:Cdn`.
