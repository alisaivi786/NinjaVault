# NinjaVault.Cdn 100.42.0.1

Date: 2026-09-28
Type: Minor

## Changes
- **Standalone package.** `NinjaVault.Cdn` no longer depends on `NinjaVault.Http`; its only dependencies are
  `Microsoft.Extensions.*` 8.0+.
- `AddNinjaVaultCdn(...)` registers only the CDN client (named `HttpClient` `NinjaVaultCdn`,
  `DependencyInjection.ServiceName`) and returns its `IHttpClientBuilder`. Logging, correlation and retries are
  attached by the application, e.g. `.AddNinjaVaultHttpLogging("NinjaVaultCdn")`, `.AddExtendedHttpClientLogging()`,
  `.AddHttpMessageHandler<MyHandler>()` or `.AddStandardResilienceHandler()`.
- README: configuration no longer includes logging; new "Logging, correlation and retries: your choice" section.
- New package icon: "Secure Storage" (storage stack guarded by the NinjaVault ninja, with a padlock).

## Why
- A public client library should not decide how an application logs. Apps that already have their own
  external-API logging (their own sink, correlation accessor or Serilog setup) can now attach it directly to the
  CDN client instead of running a second, separate logging pipeline.

## Breaking Changes
- `AddNinjaVaultCdn` no longer registers `NinjaVault.Http`. To keep the 100.41.0.x behaviour, install
  `NinjaVault.Http` and chain `.AddNinjaVaultHttpLogging(DependencyInjection.ServiceName)`; call
  `services.AddNinjaVaultHttp(configuration)` to keep binding `NinjaVault:ExternalApiLogging`.
- `DependencyInjection.ServiceName` is now also the `IHttpClientFactory` client name.
