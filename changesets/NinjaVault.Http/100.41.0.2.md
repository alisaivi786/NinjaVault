# NinjaVault.Http 100.41.0.2

Date: 2026-09-28
Type: Patch

## Changes
- `ExternalApiLoggingHandler` now decides whether to capture a response body from its headers **before**
  buffering it. Binary and multipart responses are no longer loaded into memory just to record the
  `{"omitted":true,...}` placeholder, so large downloads stream straight to the caller again.
- Responses that declare a `Content-Length` over 1 MB are never buffered for logging; they are recorded as
  `{"omitted":true,"reason":"body larger than 1 MB - not buffered or logged",...}`.
- New regression tests: `BinaryResponseBody_IsNotBufferedByTheLoggingHandler` and
  `LargeTextResponse_IsNotBufferedAndIsRecordedAsPlaceholder`.
- Rewritten package README: quick start, full configuration reference, where logs go (ILogger/Serilog vs
  custom sink), custom sink example, correlation middleware, and troubleshooting.

## Why
- With `CaptureResponseBody: true` (the default), every file download made through a logged client was fully
  buffered in memory before the caller got the stream, even though only a placeholder was logged.

## Breaking Changes
- None. Text responses over 1 MB are now logged as a placeholder instead of a truncated body.
